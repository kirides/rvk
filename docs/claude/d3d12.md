# D3D12 backend, Agility SDK, debugging

Moved out of CLAUDE.md (2026-11-13: it exceeded Claude Code's size limit). Read the file for the area you work on.

**D3D12 backend** (docs/research/dx12-game-port.md): `run.ps1 -Api d3d12` (config.toml `[vulkan] api = "d3d12"`, player setting `vulkan.api`, restart; falls back to Vulkan with a log line when SM 6.6 / binding tier 3 is missing); `-Validation` = the debug layer + GPU-based validation (messages in rvk.log as `d3d12: validation N`); gate `rvk_d3d9test --backend d3d12`. D3D12 diagnostics / gotchas (dx12-game-port.md 'Defects + WP9', hlsl-rhi.md 9.4): `RVK_EXPOSURE_LOG=1` (the engine's adapted luminance, the luminance chain, NaN count of the HDR scene every 60 frames), `RVK_NAN_BISECT=<frame>` (the draw that adds NaNs to the scene), `RVK_NO_COMPACT=1`; `RVK_SHADER_DIR` edits work for D3D12 too (bisect a slow pass by editing shaders, no rebuild; pass values with forward slashes). DXIL gotchas: translator `rvk_pow` (D3D9 pow(0,0) = 1), never index an array of a loaded block with a loop variable (`p.Get().arr[i]` loads the whole block: use `rvkRawLoad` by offset). `scripts/check-delayload.ps1` (CI) keeps d3d12 / dxgi delay-loaded; `-Perf` logs `perf: d3d12 video memory`; exclusive fullscreen is not available on D3D12 (borderless). The overlay (vendored `imgui_impl_dx12`), GPU timestamps (`-Perf` / `-PerfFrame`), PIX / RenderDoc event regions, ray tracing (DXR 1.1: RT scene, RT shadows, water RT, GI, characters through the skin compute; the vertex capture pool = a GPU upload heap with UAV access, `RingAlloc::refRw` / `GameDevice::captureAccess`), the G-buffer / GTAO, water (SSR + RT, FFT ocean), enhanced shadows and object motion run on it; PSOs are built on background threads (a draw whose PSO is pending is skipped; `rvk.log perf: d3d12 mesh arena ...` counts them); FSR / frame generation are not available on it yet (they log and stay off). Diagnostics: `-Environment 'RVK_DRED=1'` (DRED breadcrumbs / page fault in rvk.log after a device removal, also with `-Validation`), **`rvk_rhitest --validation` on D3D12 = the debug layer WITHOUT GPU-based validation since 2026-11-10 (`--gbv` adds it: under GBV the abi probe's RvkStageData dispatch alone grew the process past 12 GB, GBV's own instrumentation, our memory 0.3 GB; full `--d3d12 --validation` now 97 s / 0.47 GB peak; use `--gbv` with `RVK_ABI_ONLY` / `RVK_PICTURE_ONLY` / `RVK_PARITY_ONLY`, `RVK_RHITEST_PROGRESS=1` = per-block private bytes of the abi probe; performance.md 34); the tools' banners say `tracy: on|off`**; `RVK_NO_GBV=1` (`-Validation` without the GPU-based validation, which runs at ~0.1 fps with the RT scene on: use it for the debug layer's messages, the full GPU-based one only for short scenes), `run.ps1 -StallSeconds N` (the watchdog of a slow run), `water-compare` / `shadow-compare` / `refcompare` take `-Api d3d12`. `RVK_WP0=1` (`-Environment`) logs the `wp0:` draw-path counters; `RVK_DUMP_HLSL=<dir>` dumps every generated shader text on D3D12.

**Agility SDK 1.620.1 + debugging** (hlsl-rhi.md 6d; raytracing.md 9): the repo carries `vcpkg-overlay/directx12-agility` (+ `vcpkg-configuration.json` `overlay-ports`) = the registry port at the retail 1.620.1; `package.ps1` ships
`rvk\d3d12\D3D12Core.dll` (not the debug layer); the backend finds it in `d3d12\` beside the module or `rvk\d3d12\`, else the inbox runtime. DRED is on for every D3D12 device by default (`RVK_DRED=0` / `[debug] d3d12_dred = false` off); a removed
device (game path: `reportRemoved`; and a Vulkan `VK_ERROR_DEVICE_LOST`) writes the DRED report + a minidump to `bin\rvk\dumps\` (`core/crash_dump.*`; `[debug] crash_dumps` = unhandled-exception filter, default on); `[debug] d3d12_messages = true` /
`RVK_D3D12_MESSAGES=1` = the debug layer's messages in rvk.log without GPU based validation (`RVK_NO_GBV=1` also drops GBV from `-Validation`); `rvk_rhitest --device-lost` tests the report (`RemoveDevice`); region events (game labels + RHI regions) are PIX3 blobs
(`winpixevent` headers, no runtime DLL). New caps lines: clustered geometry, shader execution reordering (RX 7900 XTX: SER extension offered but the hint is a no-op, no OMM, no cluster geometry).
