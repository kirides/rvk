Detail distances (docs/research/lod.md; settings category Detail, player defaults trees/objects/view 2x, test baseline 1x; `lod.view` also scales the cache-in spheres and CullTree, lod.md 6): `-Setting 'lod.trees=3','lod.meshes=3','lod.view=1.5'`; rvk.log `engine: lod:` (the game's tree limits / mesh ranges), `detail distances`, `billboard fade variant`.
Frame generation (docs/research/frame-generation.md 9 / 10; F1 + F2 + F3 built): AMD FFX frame generation from `amd_fidelityfx_framegeneration_vk.dll` (vendored in `third_party/amd_fidelityfx/signedbin`, shipped in the main zip, `vk/framegen.*`): `-Setting 'framegen.mode=fsr3'` (`off | fsr3 | fsr4`, Image category = player setting; fsr4 = the ML provider, greyed / applies as fsr3 unless the API offers a 4.x provider (RDNA 4)) presents through **AMD's frame generation swapchain** (`vk/fg_swapchain.*`, provider pinned 3.1.7, callback model: the swapchain interpolates inside its present and paces the generated + real frame; our `Swapchain::setFrameGen` creates it, in-place recreate on resize / vsync, order: generator context -> WaitForPresents -> swapchain context -> swapchain; the generator's context mutex `FgSwapchain::contextMutex()` covers configure / prepare / present; the overlay is drawn by its present callback on generated AND real frames from a draw-list snapshot `Overlay::prepare / recordPrepared`); `vulkan.max_fps` / vsync = the OUTPUT rate, the pacer holds the base at half of it (`vulkan: frame pacing at ... frame generation: base = output X fps / 2`); exclusive fullscreen is switched off while it is on (`hal: exclusive fullscreen is not available with frame generation`); extra queues are requested whenever the DLL is installed (no restart); a swapchain that cannot be created falls back to the manual model with a logged reason; AMD's VK swapchain names its three events (`PresentEvent` / `InterpolationEvent` / `PacerEvent`: shared by every process with that swapchain, the cause of the FG-1 "stall", frame-generation.md 13), so `FgSwapchain::load` patches the DLL's `CreateEventW` import to drop the names (`RVK_FG_SHARED_EVENTS=1` = the old behaviour, A/B arm; `RVK_FG_TRACE=1` + `-Perf` = the DLL's Vulkan calls in a ring dumped by the hang watchdog, `fgtrace:` lines). Debug: `'framegen.manual=true'` (the generated frame is shown first and the real frame half a base interval later through our swapchain: also the capture path, `<name>_gen.png`) + `'framegen.debug=motion|depth|hudless|generated'`. rvk.log every 5 s: `framegen: swapchain: base X fps -> output Y fps (N real presents ... = 2.00 per rendered frame); present callbacks ...`, with `-Perf` also `perf: framegen present gaps (ms): mean / stddev / p1 / p50 / p99 / max, every other gap` (a spinning sampler thread on the API's present counter; `-Environment 'RVK_FG_NO_SAMPLER=1'` leaves it out for CPU measurements) and `diag: hang:` = every thread's stack when no frame is presented for 8 s (hang watchdog, `-Perf`); the overlay's fps counter shows `base -> output fps`; overlay debug commands `overlay scroll <0..1>` (Graphics tab; the Image section is at the bottom) + `move x y` / `click x y` for screenshots of drop-downs. Captures: `-Screenshots` and the `rvkcompare` / `rvk_rtwalk` bursts write `<name>_gen.png` in the manual model only (`rvk_rtwalk -Param 'load=0','burst=6','interval=1','name=fgwalk','burst_at=8','keys=MoveForward,TurnRight','pose=x;y;z;yaw','hud=1'`; rvkcompare spots freeze the game). Passes `framegen.depth / hudless / generate / debug` (`enh/framegen.*`; injection point `BeforePresent`), runs in the world only (menus / loading / pause / no main view / back buffer != swapchain size: the generator is configured disabled, camera cuts reset), forces the G-buffer on; `rvk_vktest --fg` = self-test (SKIP without the DLLs; `-Validation` shows AMD's own `rw_output` OpImageWrite errors and format-mismatch warnings: accepted, frame-generation.md 9.4; sync validation clean); `-PerfFrame` pass `framegen.generate` = 0.42 ms at 1600x900.
Upscaling / native AA (docs/research/upscaling.md; Image category): `-Setting 'upscale.mode=native_aa'` (`off` | `native_aa` | `quality` | `balanced` | `performance` | `ultra_performance` | `jitter_only`; ratios 1 / 1.5 / 1.7 / 2 / 3: the scene targets render at display / ratio, FSR outputs display size, the GUI stays sharp; forces the G-buffer on) + `upscale.sharpness` (0..1, default 0.4) + `upscale.reactive` (Advanced, default on: FSR's auto reactive mask for rain / particles / spells, from the scene copied at the `BeforeAlpha` injection point by pass `upscale.opaque`), debug `upscale.jitter_flip=none|x|y|xy`; while the post chain runs the scene image reports the output size, so ToneMap / DoF are built at display size (always on, upscaling.md 16); `upscale.cutout_thicken` (Debug tab; 0..0.5, default 0: thin cut-out strands kept ~1 render pixel wide via the translated texkill / alpha test, scaled with the render scale; steadier but heavier nets, upscaling.md 19), debug `upscale.alpha_dither` (hashed cut-out, ~20 % less net flicker, softer: upscaling.md 17); the engine's material cut-outs are the z pre-pass `texkill` of alpha - c5.w, not the alpha-test state; diagnostics `-Environment 'RVK_TRACE_MATERIAL=<name part>'` (+ `-RvkLogLevel trace` for the opaque passes' names) logs every draw state of matching materials and their entities (`d3d9: material trace`, upscaling.md 18); FSR 3.1.6 through AMD's signed FSR SDK 2.4.0 DLLs `amd_fidelityfx_loader_vk.dll` + `amd_fidelityfx_upscaler_vk.dll` (`third_party/amd_fidelityfx/signedbin`, VERSION.md = tag / hashes / signatures, copied to `bin\rvk` by run.ps1 / package.ps1; `rvk_vktest --fsr` = self-test of both providers (SKIP without the DLLs; the ML pass's validation errors from inside AMD's shaders are only a NOTE). Per-object motion (upscaling.md 9): `upscale.object_motion` (Debug tab; `off|characters|all`, default characters; skinned draws, `all` adds rigid draws that have an entity, `enh/object_motion`), rvk.log `enh: object motion: ...`. **rvkcompare spots freeze game time** (`risen.debug.time_freeze`), so characters do not animate in them: the explicit spots `hero_idle` / `pub_idle` (`freeze = false`; `-Param show_actors=1` for the pub's NPCs) run the clock (`water-compare -Spots hero_idle -Param show_actors=1 -Burst 8 -Interval 1`). **Jitter and depth** (upscaling.md 10): the camera jitter is a clip-space offset on the main view's geometry only (FrameBlock matrices stay unjittered), so a position rebuilt from the main view's depth must use `rvkUvToNdc(uv) - rvkJitterNdc(f)` (`rvk_common.glsl`; G-buffer, screen probes, material variants, shadow mask do; the engine's own post_SSM cascade draws do not). Gotcha: `shaders/include/rvk_material_variant.glsl` is embedded text compiled at run time (it does not include `rvk_common.glsl`): after editing it run `rvk_shadertool corpus corpus --gbuf`, `--gi`, `--gbuf-motion`. **Nets** (upscaling.md 12): explicit `rvkcompare` spots `net8_n/e/s/w` (player at a savegame's position near Harbour Town, camera looking N / E / S / W; `net8_s` = the large fishing net: unstable under FSR at Quality and below, clean at native AA; LOD bias / RCAS / reactive mask / FSR tuning keys do not help). `rvk_vktest --ffx-driver <path to amdvkffx64.dll>` probes AMD's driver FSR 4 provider (all calls `E_INVALIDARG`: it gates its caller; upscaling.md 13).
