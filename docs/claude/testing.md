**Real shutdown path**: `run.ps1 -GracefulExit` (after the result / `-Seconds` it closes the game window instead of killing the process, so `HalDevice::~HalDevice` -> `Device::destroy` -> the backend's teardown run; waits 60 s; prints the exit code, the faulting module from the WER event and new minidumps of `bin\rvk\dumps`; exit 3 on a crash / hang). The game's own exit crash (`SharedBase.dll+0x7caa9` / `Engine.dll+0x8f1bd`: Game.dll's static `gCTutorialAdmin` releases GUI bitmaps destroyed long before, in DLL detach; also in Original mode) and the rich presence thread's read of the dead `eCApplication` are suppressed by `engine/exit_guard.*` (any mode; docs/research/shutdown.md): every exit crash counts again. Exit faults: `bin\rvk\dumps\rvk_<stamp>_crash.txt` / `_exitfault_<n>.txt` (registers + pointees + unwound stack, also for faults inside DLL detach; `-Environment 'RVK_EXIT_TRACE=1'` = every fault of the run + the exit caller). With `-Validation` on D3D12 the teardown logs `d3d12: device teardown: objects still alive` (the debug layer's named report after every member is released): our own objects must not appear there; unnamed ones + `rhi queue` held by a still-alive DXGI swapchain are most likely the injected overlays' (Steam `gameoverlayrenderer64`, OBS `graphics-hook64`: inferred, not proven; `rvk_d3d9test` without them reports only the device). `rvk_d3d9test` case "teardown with captures" (last) tears the device down with capture chunks + timestamps alive. **Shutdown completeness (frame-ownership.md 14.26)**: risen-spass's test thread ends the process 1.5 s after the result (`exit_on_finish`, `TerminateProcess`): exit diagnostics hook `ntdll!NtTerminateProcess` and a termination from another thread waits (<= 45 s) for our device shutdown (`crashdump::deviceShutdownBegin/End`, also from the window's `WM_CLOSE` on); rvk.log `hal: device shutdown complete (N process terminations ... waited for it)` must appear in every graceful run; a shutdown not ended after 30 s writes `bin\rvk\dumps\rvk_<stamp>_shutdownhang_<n>.txt` (windows + every thread's stack, `diag::allThreadStacks`: a failed run). The engine destroys its window before it releases the device: AMD's frame generation swapchain is released at `WM_CLOSE` (`FrameGeneration::windowClosing`; its presenter otherwise waited forever in `vkAcquireNextImageKHR`). Leaked objects at `vkDestroyDevice`: `-Environment 'VK_LAYER_DUPLICATE_MESSAGE_LIMIT=100000'` lists all (the layer prints 10); `Device::destroy` destroys every variant module ever built (`d3d9: shader modules destroyed: ...`); AMD's `FrameRenderedSemaphore`s left alive are destroyed after its swapchain (`fg swapchain: semaphores of the DLL: ...`, `RVK_FG_KEEP_SEMAPHORES=1` = A/B).
