# GD3D11: research notes for the Risen Vulkan renderer

Source studied: `E:\git\github\GD3D11` at `5852b389` (2026-10-19). I only read it and changed nothing.
GD3D11 is a rendering mod for Gothic 1/2 (ZENGIN, 2002, **32-bit**). It ships as a `ddraw.dll` and
replaces the game's renderer. It has three backends: D3D11 (the default and the reference), D3D12, and
Vulkan. D3D12 and Vulkan share one renderer through a thin RHI.

Our target is different on several points that matter. Risen runs the Genome engine on D3D9 and is
**64-bit**. We want **Vulkan only**, with **dynamic rendering only**. GD3D11's biggest constraints, 32-bit
address space and D3D11 parity, don't apply to us, so many of its workarounds are optional for us.

## 2. Overall architecture

### 2.1 Interception

- **ddraw.dll proxy.** `ddraw.def` exports `DirectDrawCreateEx` and friends, plus extra exports for Daedalus
  scripts (sky textures, ImGui C API `imgui_*` at ordinals 2200+). `D3D7/MyDirectDraw*`,
  `MyDirect3DDevice7` and `MyDirectDrawSurface7` implement the COM interfaces Gothic expects. They
  translate the fixed-function stream (2D UI, fonts, the FF sky, HUD) into modern draws. The engine emulates
  FF with `FixedFunctionPipeline.h` / `PS_FixedFunctionPipe.hlsl`.
- **Textures.** They arrive through the surface wrapper: Lock/Unlock on `MyDirectDrawSurface7` creates the
  engine-side `GfxTexture` (`EngineTexture`). Texture streaming goes through `zCTexture::CacheIn`, which is
  hooked with `zCTextureLoadResourceData`.
- **Function hooks.** Microsoft Detours (`DetourAttachTyped`) hooks ZENGIN methods. Examples:
  `zCBspNodeRender` (`OnStartWorldRendering`), which **replaces the whole BSP traversal** (the mod culls
  and draws the scene itself); `zCWorld::Render/LoadWorld/VobAddedToWorld/VobRemovedFromWorld/DisposeVobs`;
  `zCVob::SetVisual/Destructor/EndMovement`; and `zCBspTree::LoadBIN`.
- **Asm patches.** `GothicMemoryLocations.h` provides `PatchAddr`, `PatchCall` and `PatchJMP`
  (VirtualProtect, memcpy, FlushInstructionCache). `HookedFunctions.cpp` holds dozens of byte patches at
  hard-coded addresses: NOPs, forced jumps, and math routines swapped for SIMD versions (`zMat4`, `zQuat`).
  Each supported executable gets its own address table (`GothicMemoryLocations1_08k.h`, `2_6_fix.h`,
  `1_12f.h`, and a Spacer variant). The build picks one per game at compile time and checks at runtime.
- **Frame boundaries.** `OnBeginFrame` is Gothic's BeginScene and `OnEndFrame` is EndScene/Present. Both
  fire in menus and in-game.
- **Launcher.** A small `ddraw.dll` checks CPUID for AVX/AVX2 and loads the matching renderer build from
  `GD3D11\Bin`.

**For Risen:** the equivalent would be a `d3d9.dll` proxy, or hooks on `Direct3DCreate9`/`CreateDevice`,
plus hooks into the Genome engine's scene/mesh/material classes. The ZENGIN addresses and classes are not
reusable. The *pattern* is: replace the engine's scene traversal with your own collect+cull, and keep the
2D/UI through the API wrapper.

### 2.2 What it extracts from the engine (Gothic-side model, `GothicAPI` and `WorldConverter`)

- **World mesh.** `WorldConverter::ConvertWorldMesh` turns `zCPolygon` triangle fans into sections
  (`WorldMeshSectionInfo` on an XZ grid) and per-material `MeshInfo`. It has a lightmap-colour fallback.
  Tangents are precomputed with MikkTSpace, and meshoptimizer is used on the meshes.
- **Static VOBs.** `zCProgMeshProto` visuals are extracted into `MeshVisualInfo`, with LODs
  (`MeshLodBuilder.h`) and welded shadow indices (`MeshShadowIndexBuilder.h`). Extraction runs
  asynchronously on worker threads (`ExtractProgMeshProtoFromModelAsync`, `AsyncVisualExtractor`).
- **Skeletal.** `zCModel` with `zCMeshSoftSkin` becomes `SkeletalMeshVisualInfo`, with bone transforms
  pulled per frame. Node attachments (weapons, heads) and morph meshes (`MorphBlend`, `MorphGpu`) are
  handled too.
- **Materials.** These are `zCMaterial` and `zCTexture`, plus `MaterialInfo` (per-texture user settings,
  normal and ORM maps loaded from `system\GD3D11\textures\replacements`). It also emulates the ZENGIN
  material FX (texAniMap, envMap, detail).
- **Lights.** `zCVobLight` becomes `VobLightInfo`. Shadowed point lights use cube maps or cube arrays
  (`PointShadow/`).
- **Camera.** `zCCamera::GetTransformDX(TT_VIEW/TT_VIEW_INV/...)`. The projection is rebuilt with
  **reversed Z** (D32_FLOAT, clear to 0, GREATER_EQUAL).
- **Sky.** The `zCSkyController_Outdoor` state drives the mod's own atmospheric scattering (`GSky`). The
  game's FF sky is also kept as a fill.
- **Vertex formats** (`VertexTypes.h`). CPU `ExVertexStruct` is 60 B (pos, normal, uv, uv2, colour,
  tangent). The GPU packing `ExVertexStructGPU` is 36 B: float3 pos, octahedral int16x2 normal, packed
  tangent, float2 uv, half uv2, colour.

### 2.3 Engine data to GPU resources (D3D12/Vulkan path)

- **Bindless everywhere.** One shader-visible heap with 65,536 slots. Shaders read through
  `ResourceDescriptorHeap[i]` (SM 6.6). Material slots go in per-draw constants.
- **Arenas.** Geometry is sub-allocated into big shared buffers: `D3D12MeshArena`, `D3D12VobArena`, the
  skeletal arena, and the attachment arena. Draws are `ExecuteIndirect` over argument buffers.
- **GPU culling.** `VobCull.hlsl` (`CSCull`, `CSPatchArgs`, count buffer), `WorldCull.hlsl` and a Hi-Z
  pyramid (`HiZ.hlsl`).
- **GPU scene** (`GPU_SCENE_PLAN.md`, `D3D12GpuScene`, `D3D12GpuWorld`). It is optional (`[Debug]
  GpuScene/GpuWorld`). Static VOBs live in a persistent instance table, grouped per visual. Draw
  templates are expanded by `CSBuildArgs` into opaque and alpha lists with GPU counts. This covers the main
  view, the 3 cascades, the rain map, and 8 point-light cube bakes. Texture streaming is driven by
  **readback feedback**: per-visual visible counts are read back 2 frames later, and the CPU then calls
  `CacheIn` and re-resolves the material slots baked into templates. Leaf MOBs (chests, doors) are frozen
  as snapshots while they are still.
- **GPU skinning.** `SkinVertices.hlsl` poses every skinned sub-mesh into a posed-vertex stream once per
  frame. All passes then draw that stream, and skeletal draws are indirect too (vertex pulling, see
  `SKELETAL_VERTEX_PULLING_PLAN.md`, referenced but not present in the repo root).
- **Uploads.** A batched uploader (4 MiB staging chunks, cap of 8, flushed at Present, at a threshold, or
  when idle) runs on a copy/transfer queue with a fence or timeline. Per-frame rings are persistently
  mapped. Constant buffers go through a per-frame ring with 256 B alignment.

### 2.4 Frame structure (modern renderer, `D3D12Scene.cpp::OnStartWorldRendering`)

This path is **Forward+, not deferred.** The `d3d12-parity` skill says outright: "Forward+ lighting only
(no deferred/G-buffer)". D3D11 additionally has deferred and tiled-deferred renderers (`ISceneRenderer`,
`D3D11DeferredRenderer`, `D3D11ForwardPlusRenderer`).

1. **Collect, once.** Visible VOBs, lights and MOBs are collected (the side effects mean it must run exactly
   once). Then `BuildFrameLightBuffer`, `UploadFrameVobInstances`, and `PrepareFrameSkeletals` (which also
   updates animation once).
2. Bind the HDR R16F scene-colour target.
3. **CSM.** Cascade matrices are computed and the per-cascade caster culls launch on the worker pool. Point
   shadow cubes and the rain shadow map are resolved, and recording fans out to worker threads
   (`BeginShadowRecording`) with one command allocator per thread per frame.
4. TAA jitter (`AdvanceJitter`) and motion constants.
5. `PrepareSky` (atmosphere solve), wetness constants, and the rain particle advance (compute).
6. Build the world, VOB and skeletal indirect commands, run GPU skinning and morph fold.
7. **Depth prepass with a motion G-buffer.** Order: world, Hi-Z, GPU VOB cull, VOBs, skeletal, vegetation.
8. Light culling (compute, tiled Forward+ grid), SSAO / **XeGTAO**, sky IBL, optional RT shadows (DXR on
   D3D12 only).
9. Join the shadow passes (`FinishShadowPasses`), then `DrawSky`.
10. **Lit geometry pass.** World, skeletal, VOBs, vegetation, opaque decals.
11. SSR history capture, low clouds, **water** (refraction copy, SSR, ocean waves and shore foam).
12. Fog graph: height fog, god rays, low-cloud composite.
13. Transparency: backdrop capture, a sorted transparency queue (particles, ghosts, alpha VOBs, poly
    strips), rain.
14. Camera velocity, then the post-FX graph: **DoF, SMAA, underwater, debug lines, TAA, bloom, luminance
    adaptation, FSR 1/2/3 upscale, resolve to the backbuffer (tonemap / HDR encode), sharpen (simple or
    CAS), and the display chain** (gamma, HDR10 PQ).
15. 2D UI (`D3D12UI2D`, a batched `UIRenderer2D`), ImGui overlay, present.

The **render graph** (`D3D12RenderGraph`) is small and pass-based. `Read`/`Write` calls carry D3D12 states
and the graph inserts barriers automatically. It also handles transient textures in an aliasing arena,
dead-pass elimination, `TransitionExternal`, and imported-resource state tracking. It is used for post FX,
fog, GTAO, water and DoF, but not for the main geometry passes. **Transient aliasing is off by default on
NVIDIA**, because Vulkan lost the device in arena-backed passes there.

## 3. The Vulkan backend in detail

The files are under `D3D11Engine/VulkanEngine/`, about 7.7k lines.

| File | Role |
|---|---|
| `VulkanCommon.h` | volk include, with `VK_NO_PROTOTYPES` and `VK_USE_PLATFORM_WIN32_KHR` |
| `VulkanLoader.cpp` | `VOLK_IMPLEMENTATION` plus result and VA logging helpers |
| `VulkanMemAlloc.cpp` | `VMA_IMPLEMENTATION` with `VMA_STATIC/DYNAMIC_VULKAN_FUNCTIONS 0` and `vmaImportVulkanFunctionsFromVolk` |
| `VulkanImGui.cpp` | compiles `imgui_impl_vulkan.cpp` with `IMGUI_IMPL_VULKAN_USE_VOLK` |
| `VulkanDevice.*` | instance, device selection, feature probe, capability report, queues and queue mutexes |
| `VulkanSwapchain.*` | Win32 surface and swapchain, present modes, HDR10, present wait, retired swapchains |
| `VulkanRhi*.cpp/.h` | the translation of the D3D12-shaped RHI: device, command list, pipeline, queue, swapchain, formats, state |
| `VulkanSpirvPatch.h` | header-only SPIR-V rewriter that turns a uniform block into a push-constant block |

### 3.1 Design: an RHI shaped like D3D12

`RHI/Rhi.h` and `RhiCmdList.h` are about 800 lines. They use **d3d12.h structs and enums as the
vocabulary**: `D3D12_RESOURCE_DESC`, `D3D12_RESOURCE_STATES`, root parameters, PSO descs, command
signatures. The objects are refcounted `Rhi::` classes that work with `ComPtr`. The D3D12 backend is thin
forwarders. The Vulkan backend *translates*, in the same spirit as vkd3d-proton but much smaller.
`Rhi::CmdList` filters redundant state above the virtual call. This kept the conversion of the 33k-line D3D12
renderer mechanical, at the cost of Vulkan-side emulation:
- **Descriptor heap.** A `Descriptor` record array stands in for CPU handles. GPU handles encode (heap id
  << 32 | index). Writes to the shader-visible heap are mirrored into the bindless set.
- **GPU VAs** are opaque: `(buffer id << 32) | offset`.
- **Fences** use D3D12 semantics over timeline semaphores. Queue signals and waits become possibly empty
  submits.
- **Implicit rendering scopes**, as in DXVK/vkd3d. `OMSetRenderTargets` only records the attachments. The
  first draw opens `vkCmdBeginRendering`. A barrier, copy, dispatch or target change closes the scope.
  Clears become `loadOp=CLEAR` or `vkCmdClearAttachments`, and Discard becomes `DONT_CARE`. There are
  escape hatches, `BeginNativeRendering`/`EndNativeRendering`, for raw recorders such as imgui_impl_vulkan
  and FFX.
- **Per-subresource layout tracking** on `ResourceImpl`. The neutral D3D12 state maps through `MapState` to
  a `(stage2, access2, layout)` triple (plan section 5.6). If a transition's Before disagrees with the
  tracked layout, the barrier is widened to ALL_COMMANDS/MEMORY_WRITE and dev builds log it.
  Read-only-to-read-only is not treated as stale.
- **A global barrier at the head of every submit**, because D3D12 flushes between `ExecuteCommandLists` and
  Vulkan doesn't.
- **Deferred destruction** is keyed on the queue serial (timeline). It runs only once every submission so
  far, *and every list still being recorded*, has retired.
- **Initial layouts.** Images start in UNDEFINED. The initial layout transitions are queued and recorded ahead
  of the next submit.

### 3.2 Vulkan version and extensions (`VulkanDevice.cpp::CheckRequirements`)

- The instance requests **apiVersion 1.4** so that 1.4 devices expose their 1.4 core features. The minimum is
  **1.3** for both loader and device.
- **Required instance extensions:** `VK_KHR_surface`, `VK_KHR_win32_surface`.
- **Required device extensions:** `VK_KHR_swapchain`; **push descriptors** (`VK_KHR_push_descriptor` or 1.4
  core) with `maxPushDescriptors >= 18`; **`VK_EXT_mutable_descriptor_type`** (VALVE alias accepted).
- **Required features:**
  - 1.0: multiDrawIndirect, drawIndirectFirstInstance, samplerAnisotropy, textureCompressionBC,
    imageCubeArray, independentBlend, depthClamp, shaderClipDistance,
    shaderStorageImageRead/WriteWithoutFormat.
  - 1.1: shaderDrawParameters.
  - 1.2: timelineSemaphore, descriptorIndexing, runtimeDescriptorArray, descriptorBindingPartiallyBound,
    VariableDescriptorCount, UpdateUnusedWhilePending, SampledImage/StorageImage UpdateAfterBind,
    shaderSampledImageArrayNonUniformIndexing, **scalarBlockLayout**, shaderFloat16, drawIndirectCount,
    shaderOutputLayer, separateDepthStencilLayouts.
  - 1.3: **dynamicRendering, synchronization2**, maintenance4, shaderDemoteToHelperInvocation.
  - Subgroup ballot in compute.
- **Required limits:** 65,536 update-after-bind sampled and storage images per stage and per set,
  `maxPerStageUpdateAfterBindResources >= 65536`, and `maxBoundDescriptorSets >= 2`.
- **Optional, probed, logged and gated:**
  - **`VK_EXT_device_generated_commands`** (with maintenance5 and BDA). It is **effectively required for
    performance**: without it, `ExecuteIndirect` is replayed on the CPU from host memory, and the #527
    commit calls the frame time "unacceptable".
  - `VK_EXT_extended_dynamic_state3` (blend enable/equation/write mask, depth clamp, polygon mode,
    alpha-to-coverage made dynamic so PSOs share a VkPipeline).
  - `VK_KHR/EXT_vertex_attribute_divisor`.
  - `robustness2` (nullDescriptor, robustBufferAccess2/robustImageAccess2).
  - memory_budget, memory_priority, pageable_device_local_memory.
  - device_fault, device_address_binding_report, AMD_buffer_marker, NV_device_diagnostic_checkpoints,
    NV_device_diagnostics_config (Aftermath).
  - swapchain_colorspace, hdr_metadata, KHR/EXT swapchain_maintenance1 and surface_maintenance1,
    get_surface_capabilities2, present_id/present_wait and present_id2/present_wait2.
  - calibrated timestamps, debug_utils, validation_features.
- **Logged only:** GPL, descriptor_buffer, descriptor_heap, anti_lag, NV low latency 2, maintenance6.
- **Robustness is on by default.** It enables robustBufferAccess and robustImageAccess (plus the
  robustness2 variants), because "D3D12 bounds-checks every descriptor access ... and the shaders rely on
  it; NVIDIA does neither without these". `-VKNOROBUST` turns it off.
- **Adapter selection** matches DXGI's high-performance adapter by `deviceLUID`. HDR output info and display
  modes still come from DXGI.
- On any failure (no loader, no 1.3, a missing feature, or a DXC without SPIR-V), the engine **falls back to
  D3D11**. A failed `InitScene()` leaves Vulkan running menus and UI only.

### 3.3 Descriptors and binding model

- **Set 0:** a per-root-signature **push-descriptor** set. DXC register shifts are `b`→0+, `t`→16+,
  `u`→32+, `s`→48+ (space 0 only). Root CBVs become UBOs, root SRV/UAV become SSBOs, table SRVs become
  sampled images resolved from the heap's CPU mirror, table UAVs become storage images, and static samplers
  become **immutable samplers**.
- **Set 1:** **one mutable-type descriptor array of 65,536 entries**, update-after-bind and partially
  bound. Its slot indices are the same as D3D12's SRV heap. `-fvk-bind-resource-heap 0 1` makes DXC lower
  `ResourceDescriptorHeap[]` onto it. The mutable types are sampled image, storage image, plus UBO when
  `HeapUniformBuffers` (3 heap-indexed CBVs).
- **Root constants.** By default they are coalesced into one frame-ring UBO allocation and bound with a push
  descriptor. **Per-draw constants** (`D3D12RootLayout::AddPerDrawConstants`) become **real push
  constants**. The HLSL is not changed for this: `VulkanSpirvPatch.h` rewrites the uniform block in the
  SPIR-V into a push-constant block at PSO creation. `tools/check_push_constants.py` together with
  `tools/spirv_push_test` validates the rewrite. If a stage can't be rewritten, it falls back to a UBO
  (`m_UboFallback`).
- **Indirect.** A command signature made of "push constants + one draw" becomes a
  `VkIndirectCommandsLayoutEXT`, executed with `vkCmdExecuteGeneratedCommandsEXT` using
  `sequenceCountAddress` for GPU counts. Preprocess memory comes from 4 MiB per-allocator chunks.
  Everything else is replayed on the CPU. `VkDrawIndexedIndirectCommand` is byte-identical to
  `D3D12_DRAW_INDEXED_ARGUMENTS`.
- No descriptor buffers and no `VK_EXT_descriptor_heap` yet; both are only logged.
  `VK_EXT_descriptor_heap` is "evaluate later".
- **Worker-thread texture loads** write heap descriptors concurrently. A freed heap slot is recycled only after
  its timeline value has retired.

### 3.4 Pipelines

- PSOs are built from `D3D12_GRAPHICS_PIPELINE_STATE_DESC`-shaped descs with `VkPipelineRenderingCreateInfo`.
  There is no VkRenderPass anywhere, ImGui included.
- **Large dynamic state set:** viewport, scissor, topology, vertex stride, stencil ref, blend constants,
  primitive restart, cull mode, front face, depth test/write/compare, stencil test/op/masks, depth bias
  enable and value, plus EDS3 states when available. Graphics PSOs that differ only in dynamic state
  **share one `VkPipeline`** through a device-wide map keyed by the baked state (`AcquireSharedPipeline`,
  thread-safe publish with race resolution).
- Pipelines without vertex bindings must not declare a dynamic stride (`VUID-vkCmdDraw-pStrides-04913`).
- **Persistent `VkPipelineCache`.** It lives at `system\GD3D11\cache\vulkan_pipelines.bin`. The header is
  validated on load, the cache is saved after creation goes quiet (write to `.tmp`, then
  `MoveFileEx`), and it is saved again on shutdown.
- D3D winding is mapped directly (`FrontCounterClockwise=FALSE` → `VK_FRONT_FACE_CLOCKWISE`). Y is flipped
  with a **negative viewport height**, not `-fvk-invert-y`.

### 3.5 Memory (VMA), uploads, frames in flight

- VMA with `vulkanApiVersion = 1.3`, **`preferredLargeHeapBlockSize = 16 MiB`** (the 256 MiB default
  maps whole blocks and would eat 32-bit VA), plus the memory budget, memory priority and BDA flags.
  Placement heaps (`HeapImpl`) are a single VMA allocation that placed (aliased) images bind into, with a
  bounds check on offset + size.
- **Per-frame `CommandAllocatorImpl`.** One command pool and command buffers, plus an upload ring of 1 MiB
  chunks (max 16) for root constants and dynamic data, plus a DGC preprocess ring.
- A dedicated **transfer queue** is used when the device has one, else graphics. **`vkQueueSubmit` and
  present are guarded by a mutex** because Gothic loads textures on worker threads.
- Device-local buffers keep a host **mirror** of the last copy for CPU replay of indirect args.
- **Frames in flight:** `kBackBufferMax = 3` and `kBackBufferCount = 3` by default. The frame slot is
  `counter % N` and is kept *separate from the swapchain image index*.
- **Never read host-visible memory on the CPU unless it is cached.** ReBAR and write-combined reads crawl.

### 3.6 Swapchain and present

- Win32 surface on the game's HWND, min 2 images. FIFO for vsync. For uncapped it uses IMMEDIATE, else
  MAILBOX, else FIFO. With **swapchain_maintenance1** it switches present mode per present without a
  rebuild (`VkSwapchainPresentModesCreateInfoKHR`). Otherwise it recreates.
- **One present semaphore per swapchain image.** Present fences are used when maintenance1 is available.
  Retired swapchains are kept until nothing presents from them. On a vsync change it waits for the present
  fence.
- The swapchain recreates on OUT_OF_DATE/SUBOPTIMAL and skips frames while minimized.
- **HDR10:** `A2B10G10R10_UNORM_PACK32` with `HDR10_ST2084`, plus `vkSetHdrMetadataEXT`. The swapchain
  format is decoupled from the backbuffer format.
- **Frame latency.** DXGI's waitable object is emulated by waiting on the queue timeline of present
  N-(latency-1). present_wait/present_wait2 are opt-in (`-VKPRESENTWAIT`, FIFO only), because under FIFO on
  AMD they paced frames in back-to-back pairs (~0 / 16.7 ms), "which puts ZENGIN into slow motion".

### 3.7 Shader compilation

- **One HLSL source for D3D12 and Vulkan.** The 53 files in `Shaders/D3D12/` contain **zero `__spirv__`
  branches**. They are compiled **at runtime** with the **DXC COM API** (`IDxcCompiler3` from a dynamically
  loaded `dxcompiler.dll`), to DXIL SM 6.6 or to SPIR-V. This enables hot reload. D3D11 uses FXC
  (`D3DCompileFromFile`) separately for its SM5 shaders.
- **SPIR-V arguments** (`D3D12ShaderBackend.cpp::AppendSpirvArguments`): `-spirv
  -fspv-target-env=vulkan1.3 -fvk-use-dx-layout -fspv-use-unknown-image-format
  -fvk-support-nonzero-base-instance -fvk-b-shift 0 0 -fvk-t-shift 16 0 -fvk-u-shift 32 0 -fvk-s-shift 48 0
  -fvk-bind-resource-heap 0 1`, plus `-enable-16bit-types` and `-O3`, or `-Zi -Od/-O1` in debug.
- The **on-disk shader cache** is under `shadercache\Vulkan\`. The key includes the target, an args revision
  (`kSpirvCacheArgsRevision`), and the hashes of every resolved `#include`, recorded by the include
  handler.
- The **runtime probe** `IsSpirvCodegenAvailable()` compiles a trivial `-spirv` shader. The Vulkan SDK's DXC
  is x64-only, so for this x86 game they ship their own x86 `dxcompiler.dll` with SPIR-V codegen
  (`blobs/libs`). `dxil.dll` is not needed for SPIR-V.
- **Offline tooling** (Python, needs the Vulkan SDK):
  - `tools/validate_spirv.py` greps every `CompileFromFile(file, entry, target, defines)` in the D3D12
    sources, compiles each one with the engine's args, and runs `spirv-val --scalar-block-layout`.
  - `tools/check_vk_bindings.py` checks that the set-0 binding types the root-signature lowering assumes
    match what the shaders declare.
  - `tools/check_push_constants.py` checks the push-constant rewrite.
  - `tools/dxc_x86` is a dxc.exe stand-in that loads a given `dxcompiler.dll`.

### 3.8 Debugging and tooling

- `VK_EXT_debug_utils` object names and labels. The validation layer is on in dev builds when a 32-bit layer
  is registered (`-VKVALIDATION`/`-VKNOVALIDATION`). Messages are throttled per ID, written to Log.txt, and
  list the named objects.
- **GPU breadcrumbs:** begin/end markers written to host memory and dumped on device loss. `-VKDRAWCRUMBS`
  adds one per draw/dispatch named after its pipeline (`File.hlsl:Entry`).
- On device loss: `VK_EXT_device_fault` output, plus the address-binding report to **name the object behind
  a fault address**, plus AMD buffer marker / NV checkpoints.
- Command-line switches: `-VKAFTERMATH` (NVIDIA), `-GPUHEAPCHECK`, `-VKNODGC`, `-VKNOTIMESTAMPS`,
  `-VKNOPRESENT`, `-VKNOCHECKPOINTS`, `-VKNOROBUST`.
- Tracy GPU zones use timestamps. RenderDoc works, and its injected validation output is captured too.

### 3.9 State as of 2026-10-19

- The backend is **experimental**. It landed on 2026-09-28 (#527, AI-assisted) and has had about 3 weeks of
  fixes since. The maintainer runtime-verifies on an AMD RX 7900 XTX. There is no test suite. Correctness
  is checked by playing.
- Per the #527 message, D3D12 and Vulkan perform about the same on AMD. At a 60 fps lock, Vulkan uses about
  30% GPU against about 48% for D3D12.
- **Works:** menus and UI, ImGui, the full scene (world, VOBs, skeletal through DGC, shadows, point cubes,
  water, sky, transparency, post FX), and **FSR 1/2/3** since #544. `CLAUDE.md` still says "Not yet on
  Vulkan: FSR 3", which is out of date. HDR10 works.
- **Known problems from recent commits:**
  - NVIDIA device loss in render-graph passes with aliased transient textures (aliasing is now off by
    default on NVIDIA).
  - NVIDIA faults "repeatedly at the same address in different passes", still under investigation with the
    new fault-address tooling.
  - NVIDIA misreads some root constants on D3D12 (worked around with CBVs).
  - Barrier sync scopes had to be legalised.
  - Stale-layout transitions are widened and logged.
  - Without DGC the CPU replay is too slow.
- The plan's "Phase 5" items are partly done: push constants for hot blocks, the pipeline cache, and DGC
  are done. Async compute, transfer-queue image ownership transfer, and anti-lag are not.
- `VULKAN_IMPLEMENTATION_PLAN.md` still has the header "Status: proposal ... Nothing implemented yet", which
  is stale. Its sections 4-5 describe the design that was actually built.

## 5. Build setup

- **vcpkg manifest** (`vcpkg.json`, pinned `builtin-baseline`). Triplet `x86-windows-static-md` (we'd use
  `x64-windows-static-md`). Packages: `directxmath`, `directxtk`, `directx-headers`, `directx12-agility`,
  `sqlite3`, **`volk`, `vulkan-headers`, `vulkan-memory-allocator`**. `VCPKG_ROOT` must be set. Both
  MSBuild (vcpkg MSBuild integration) and CMake presets use the manifest.
- **The canonical build is the `.vcxproj`.** VS 2026 / v145, C++23, ~14 configurations. CMake
  (`CMakePresets.json`, VS or Clang+Ninja) **parses the source list out of the vcxproj**
  (`gd3d11_collect_vcxproj_sources`) and sorts sources by size for `/MP`. The maintainer says not to use
  CMake for compile checks. Compiling from Linux uses clang + xwin (`cmake/msvc-clang-linux.cmake`) and is
  unverified since the move to vcpkg.
- `pch.h` is force-included (`/FI`). Third-party sources are excluded from the PCH. Helper scripts:
  `tools/vcxproj_add.py`, `vcxproj_sort_sources.py`.
- **Shaders are not compiled in the build.** HLSL ships as source and is compiled at runtime (D3D11: FXC;
  D3D12/Vulkan: DXC). CMake's deploy step copies `Shaders/` next to the game. `dxc-bin/` is **empty**. The
  real `dxcompiler.dll`/`dxil.dll` (x86 with SPIR-V) live in `blobs/libs/`, alongside `d3dcompiler_47.dll`,
  the FFX DLLs, assimp and HBAO+.
- **Gotchas they documented:**
  - Compile volk's implementation yourself with `VK_USE_PLATFORM_WIN32_KHR`. The vcpkg `volk.lib` is built
    without platform defines, so the Win32 surface functions are missing from it.
  - Don't use the vcpkg `vulkan` port. It needs the SDK installed. Use `vulkan-headers` and load
    `vulkan-1.dll` with volk, with no link to `vulkan-1.lib`, so there is no hard dependency and fallback
    stays possible.
  - Build VMA with `VMA_STATIC_VULKAN_FUNCTIONS 0` and `VMA_DYNAMIC_VULKAN_FUNCTIONS 0`, then call
    `vmaImportVulkanFunctionsFromVolk`.
  - The Vulkan SDK's dxc is x64-only. This doesn't matter for x64 Risen: we can ship the SDK's or a
    release's x64 `dxcompiler.dll`.
  - The validation layer needs a registered layer of the matching bitness.
  - The clangd/IDE diagnostics are misconfigured. Trust MSBuild.
  - The post-build copy fails on other machines because it targets the maintainer's game folder.

## 6. Lessons and pitfalls for a Vulkan renderer injected into an old game

**Integration and engine:**
1. **Collect once per frame, and know when the "real" world render is.** Gothic calls the world render
   several times per frame, for example once per inventory tile. GD3D11 draws only on the first
   `OnStartWorldRendering` after a Present (`m_PresentPending`). Expect similar re-entrancy in Genome.
2. **The game loads textures on worker threads.** Guard queue submit/present and descriptor-set writes, or
   funnel them to the render thread. Recycle descriptor slots only after their timeline value has retired.
3. **Texture streaming and residency belong to the engine** (`CacheIn`). If GPU-built commands bake
   material slots, use feedback readback to keep textures resident and to re-resolve evicted slots.
   Otherwise you read freed slots. Rule: don't cache a "fallback texture" result into anything persistent,
   such as baked shadow cubes.
4. **Frame pacing affects game simulation.** Present-wait pacing in back-to-back pairs made ZENGIN run in
   slow motion. Keep pacing simple (FIFO plus a timeline-based latency wait). Test with the game's own
   timer.
5. **Static vs dynamic objects.** "Static" means the engine hasn't moved the object since load. Hook the
   engine's move/remove notifications and hand objects between a persistent GPU scene and a per-frame CPU
   path.
6. **Fall back cleanly.** Any init failure must leave the game playable. GD3D11 falls back to D3D11. We have
   no fallback renderer, so we should fall back to the game's own D3D9 path, that is, not hooking at all.
   Probe everything up front and log a full capability report to the log file.
7. **Reversed-Z, a negative viewport height for D3D-convention clip space, and D3D winding mapped
   directly** (`CW` front = D3D default). Verify once with an asymmetric mesh.
8. **Minimise per-frame allocations.** Use rings everywhere, drop and log on overflow, and never silently
   truncate. This rule came from 32-bit VA, but it is good practice on x64 too.

**Vulkan specifics:**
1. **D3D-isms DXC needs for HLSL→SPIR-V:**
   - `-fvk-support-nonzero-base-instance` is mandatory if `SV_InstanceID` is used with a non-zero start
     instance (D3D excludes the base, Vulkan's InstanceIndex includes it).
   - `-fspv-use-unknown-image-format` plus the storage-image read/write-without-format features. Otherwise
     DXC guesses `Rgba32f`.
   - `scalarBlockLayout` for StructuredBuffer strides 12/20/24.
   - `-fvk-use-dx-layout`.
   - `[[vk::push_constant]]` only works on a global struct or `ConstantBuffer<T>`, not on a `cbuffer`, and
     at most one per entry point.
   - `[[vk::builtin("DrawIndex")]]` is VS-only.
2. **Robustness.** D3D12/D3D11-style shaders silently rely on bounds-checked descriptor access. NVIDIA needs
   `robustBufferAccess`/`robustImageAccess` (plus robustness2 `nullDescriptor`) to match.
3. **D3D implicit state promotion/decay doesn't exist in Vulkan.** Record real transitions. The first use of
   an aliased image must transition from UNDEFINED. A barrier whose Before disagrees with the tracked layout
   is a bug. Widen it and log it in dev builds.
4. **Barrier sync/access pairs must be legal.** They had to add a legalisation table.
5. **Transient-texture aliasing is risky.** It caused device loss on NVIDIA. Make it optional and off by
   default until proven.
6. **Indirect draws with per-draw state.** Core Vulkan can't change push constants or bindings per indirect
   draw. Either use DGC (EXT, AMD/NVIDIA recent drivers only) or design for it: vertex pulling, a per-draw
   index read through `DrawIndex`/`gl_DrawID` or `firstInstance`, and one big index/vertex buffer, so that
   plain `vkCmdDrawIndexedIndirectCount` suffices. **For a new codebase, design for the core path.** Don't
   depend on DGC.
7. **Implicit scope splitting costs bandwidth** (extra load/store). In a native renderer, open rendering
   scopes explicitly per pass.
8. **Present:** one semaphore per swapchain image, not per frame slot. The frame slot is `counter % N`,
   separate from the acquired image index. Keep retired swapchains alive until their presents finish.
   Recreate on OUT_OF_DATE/SUBOPTIMAL. Skip frames while minimised.
9. **Never read host-visible, uncached memory on the CPU.** Use `HOST_CACHED` for readbacks.
10. **A dynamic vertex stride with no vertex bindings** triggers a validation error
    (`VUID-vkCmdDraw-pStrides-04913`).
11. **Persist the VkPipelineCache.** Validate its header against the device and write it atomically.
12. **Invest early in device-lost diagnostics:** breadcrumbs, device_fault, address-binding report, and
    object names. Most of GD3D11's recent Vulkan commits are device-loss hunts on NVIDIA.

**Process and tooling:**
- Offline-validate every shader permutation with `spirv-val` in CI, and check binding types against the
  pipeline-layout lowering.
- Build validation layers of the correct bitness. Validation is memory-hungry, which was critical in a
  32-bit process and is fine on x64.
- Their approach was a written plan, then a capability probe, then a platform smoke test (clear + present
  on the game window across all window modes, alt-tab, resize, minimize), then menus/UI, then scene
  subsystems one at a time. That order de-risks the integration unknowns first and is worth copying.

### Vulkan version implications for us

GD3D11 requires 1.3 + push_descriptor + mutable_descriptor_type (+ DGC in practice). For Risen, a lower
floor is realistic:
- **Baseline:** 1.3 core (dynamicRendering, synchronization2, maintenance4, demote, timeline,
  descriptor indexing, drawIndirectCount, scalar layout). This is comfortable, and current Windows drivers support it
  on roughly NVIDIA Maxwell+, AMD GCN4+/RDNA and Intel Gen9+. NVIDIA Kepler and older GCN stop at 1.2.
  Verify this against gpuinfo.org before fixing the floor. A 1.2 + `VK_KHR_dynamic_rendering` +
  `VK_KHR_synchronization2` floor is possible but adds little reach.
- **Avoid `VK_EXT_mutable_descriptor_type`.** Write HLSL with typed bindless arrays (separate bindings for
  `Texture2D[]`, `TextureCube[]`, `RWTexture2D[]`, `ByteAddressBuffer[]`, `SamplerState[]`) instead of
  `ResourceDescriptorHeap`. This drops the mutable-type requirement.
- **Treat `VK_KHR_push_descriptor` as optional** (it is core in 1.4). Push constants plus a per-frame
  descriptor set or BDA can cover the same needs.
- **Don't rely on DGC.** Use the core indirect-count path described above.
- **Optional extras:** EDS3, swapchain_maintenance1, present_wait, HDR metadata, device_fault, memory budget.
